# Truong Tho — ward-level decision support

Companion release for:

> Reactivating Legacy Stakeholder Data for Ward-Level Decision Support: A Case Study of Survey and Open Geospatial Predictors in Truong Tho, Vietnam

This folder is what you push to GitHub (or attach to OSF/Zenodo). It matches the manuscript’s **Data and code availability** section: coding audit, 130-item gold standard, local LLM configurations, raw zero-shot responses, evaluation scripts, generated tables, and the analysis notebook. Household coordinates and coder names/emails are **not** included.

## What is in here

| Path | Contents |
|---|---|
| `human_coding/` | Eight-code frame, 198-segment sample (no row IDs), six anonymised coder exports (A–F), adjudication log, 130-item gold standard, audit script |
| `llm_benchmark/` | Standard-library runner (`benchmark.py`), recorded Ollama configs, 21 raw run files, independent audit script |
| `results/llm_benchmark_20261008/` | Recomputed tables, class/subgroup results, duplicate-label checks, cluster-bootstrap sensitivity |
| `tables/` | CSV tables generated by the analysis pipeline |
| `analysis/` | Harmonisation codebook, scalar results JSON, and the end-to-end notebook (needs restricted microdata) |

**Not in this release**

- Survey microdata with household coordinates (available from the corresponding author under a data-sharing agreement)
- The interactive dashboard (it embeds geolocated points)
- Coder names, emails, or affiliations (replaced by letters A–F)

## Reproduce RQ4 (human reliability)

Python 3.10+, `pandas`, `numpy`, `scikit-learn`:

```bash
pip install -r requirements.txt
python human_coding/audit_human_coding.py
```

Expected headline numbers (manuscript Table 10): Fleiss’ κ ≈ 0.456 on 197 complete six-rater cases; 130-item single-label gold (123 strict majority + 7 adjudicated). Participation-mode fields (66 items) remain outside the single-label benchmark.

## Reproduce RQ4 (zero-shot local models)

The recorded comparison used Ollama 0.40.1, temperature 0, max 32 tokens, three zero-shot repeats, seed 20261008 for bootstrap. To **re-evaluate existing runs** (no GPU required):

```bash
python llm_benchmark/audit_llm_results.py
python -m unittest llm_benchmark/test_benchmark.py
```

To **rerun** a configuration against a local OpenAI-compatible endpoint:

```bash
cd llm_benchmark
cp config.example.json config.json
# edit endpoint, model id, and server_metadata
python benchmark.py run --config config.json --out runs/my_model
python benchmark.py evaluate --out runs/my_model --bootstrap 2000
```

Do not put API keys in JSON. Use `LLM_API_KEY` if the endpoint requires a bearer token. Gold labels are read only by `evaluate()`, never by `run()`.

## RQ1–RQ3 notebook

`analysis/Paper4_Analysis.ipynb` reproduces the model ladder and barrier tables from the 2023 survey workbooks and the Paper 1 open-data feature table. Those source files contain coordinates and are not in this repository. Open-data product identifiers are listed in the manuscript (Table 2).
